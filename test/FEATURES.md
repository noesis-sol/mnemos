# Features and their tests

mnemos is a read-only MCP server (TypeScript, Node >=22.13, npm) that reads Chrome's `Bookmarks`
JSON file and answers five MCP tools over stdio. `src/lib.ts` holds all the logic,
`src/index.ts` is the MCP wiring, `src/icon.ts` is generated by `scripts/build-icons.mjs` from
`assets/`. Tests use Node's built-in runner (`node:test`) against the compiled `dist/` and the
synthetic fixture `test/fixtures/bookmarks.json`, injected through `CHROME_BOOKMARKS_PATH`.

## Suites

| Suite | Runner | Command | What it runs |
|-------|--------|---------|--------------|
| dependencies | `scripts/check-fast.sh` | `npm ci --ignore-scripts` | only when `node_modules` is missing or older than `package-lock.json` |
| build | `scripts/check-fast.sh` | `npm run build` | `tsc`, type-checks `src/` |
| unit tests | `scripts/check-fast.sh` | `npm test` | builds, then `node --test`, which finds `test/*.test.js` itself (118 tests, ~1s) |
| published package (e2e) | `scripts/check-full.sh` | `node --test e2e/package.e2e.js` | `npm pack --json` into a scratch directory (runs `prepare`, so builds again), unpacks the tarball with `tar`, checks its files and bin, starts the server through the bin (4 tests, ~2s) |

`npm test` runs `node --test` with no file arguments, so Node's runner discovers the test
files: a new file named `test/<feature>.test.js` runs with no edit to `package.json`. On every
supported Node (checked on 22 and 24, which match glob patterns) the runner skips `node_modules/` and runs every `.js` file under `test/` and
every `*.test.js`, `*-test.js`, `*_test.js`, `test-*.js` or `test.js` elsewhere, `dist/`
included. So keep helper modules out of `test/` or give them no top-level side effects, and
keep test files out of `src/` (tsc would copy them into `dist/`, where they would run too).
Suites too slow for `npm test` live in `e2e/` with names none of those patterns match
(`<feature>.e2e.js`), and `scripts/check-full.sh` runs each by path.

Runner times on macOS, Node 24, three runs each with `node_modules` installed:

- `scripts/check-fast.sh`: about 2.3s warm (the first run after a build cache miss is slowest)
- `scripts/check-full.sh`: about 3.8s warm (check-fast, then packs, unpacks and starts the package)

CI (`.github/workflows/ci.yml`) runs `npm ci`, `npm test` and `node --test e2e/package.e2e.js`
on ubuntu, macOS and Windows with Node 22 and 24.
`test/node-floor.test.js` keeps `engines.node` (`>=22.13`, for `node:sqlite`), the lockfile's
root entry and that matrix in step.

## MCP server start and handshake

- **Reached by**: `npx -y mnemos-mcp` or `node dist/index.js` (the `bin` in `package.json`); an
  MCP client connects over stdio and sends `initialize`, then `tools/list`.
- **Tests**: `test/server.test.js` (e2e: spawns `dist/index.js` with `process.execPath` and drives
  it with the SDK's `Client`): the five tools are listed with descriptions and object input
  schemas; a tool call round-trips; a missing bookmarks file comes back as `isError`.
  `test/server-info.test.js` (same e2e setup): `serverInfo` has name `mnemos` and the
  `package.json` version, six SVG or PNG data-URI icons; the `instructions` string mentions
  `search_bookmarks`; the capabilities include `tools`.
  `e2e/package.e2e.js` starts the unpacked package through its bin file, directly on POSIX so
  the shebang runs (see Published package).
- **Untested**: nothing known.
- **Tickets**: mnemos-2gg.4 (serverInfo, instructions, icons); mnemos-2gg.12 (the bin through its shebang)

## search_bookmarks

- **Reached by**: tool `search_bookmarks(query, folder?, limit?)`; `lib.searchBookmarks`.
- **Tests**: `test/tools.test.js` (unit against the fixture): AND-matching across title, URL and
  folder path; matching through the folder path; Greek query; empty query rejected; word-start
  matching (`ai` misses Gmail and Painting, prefixes match); `total_matches` before truncation;
  folder filter with word-boundary segments; unmatched folder filter note; blank folder filter
  ignored; nodes missing `type`; 5,000-level nesting. `test/lib.test.js` (unit):
  `queryMatches` word starts, Unicode. `test/search-limits.test.js` (unit): the plain note when
  nothing matches and no (or a blank) folder filter is given, without `list_folders`; `limit: 0`
  and `limit: -3` give an empty list with the true `total_matches`; on a generated file with 250
  matches the default limit returns 100 and `limit: 500` returns 200; `c++` and `(2024)` match
  literally; results come back in document order (pre-order, across roots). `test/server.test.js`
  (e2e): one call by query, one with `limit: 1`.
- **Untested**: the `folder` argument over the wire.
- **Tickets**: mnemos-2gg.11 (the `folder` argument over the wire)

  default Chrome directory (`HOME`, `LOCALAPPDATA`, `XDG_CONFIG_HOME`); `lib.chromeBase`,
  `lib.bookmarksPath`, `lib.loadRoots`.
- **Tests**: `test/lib.test.js` (unit): `chromeBase` per platform, `LOCALAPPDATA` and
  `XDG_CONFIG_HOME` honoured, empty variables treated as unset; `bookmarksPath` override and empty

- **Untested**: nothing known.

## Local index store

- **Reached by**: nothing yet; `src/index-store.ts` (`IndexStore.open`, `cacheDir`,
  `indexFile`) is the semantic-search index the background embedder and page fetcher will use
  (epic mnemos-tc4). One `node:sqlite` file in WAL mode per Bookmarks file, in
  `MNEMOS_CACHE_DIR` or the OS cache directory.
- **Tests**: `test/index-store.test.js` (unit, every store in a temporary `MNEMOS_CACHE_DIR`):
  `cacheDir` per platform with the environment injected (`MNEMOS_CACHE_DIR`, `XDG_CACHE_HOME`
  absolute only, `LOCALAPPDATA`, empty variables unset); `indexFile` naming; create, reopen, and
  rebuild of an older or newer `schema_version`; a garbage file, an overwritten header and a
  damaged page deep in the file (found by `PRAGMA quick_check` at open) moved aside and rebuilt;
  `isCorrupt`; bookmark upsert (unchanged rows untouched, a new `text_hash` drops the vector,
  descriptions kept), delete and sync, with a URL's page and chunks kept until its last bookmark
  goes; same URL in two folders as two rows; Float32 BLOB round trip bit for bit; nearest
  bookmarks and chunks by dot product; pages and chunks; a model or revision change dropping every
  vector and keeping the rows; the lease acquired, renewed, expired, taken over and released
  between two stores on one file.
- **Untested**: corruption that appears while a store is open (callers see `isCorrupt` errors
  and reopen); two processes, rather than two stores in one process, sharing the lease.

## Page fetch policy and safe fetch

- **Reached by**: nothing in the server yet (the background page fetch, mnemos-tc4.9, will call
  it); `src/fetch.ts`: `checkUrl`, `isBlockedAddress`, `isTokenLike`, `fetchConfig`

- **Tests**: `test/fetch-policy.test.js` (unit, table-driven, no network): non-web schemes;
  `isBlockedAddress` over IPv4 private, loopback, link-local, CGNAT and unspecified ranges, IPv6
  loopback, unique-local, link-local (with zone id) and site-local, IPv4-mapped (dotted and hex),
  IPv4-compatible, NAT64 and 6to4; private literals in URLs including `127.1`, `2130706433`,
  `0x7f.0.0.1` and bracketed IPv6, and `.local` / `.localhost` names; token-like query names
  (split on punctuation and camelCase) and path segments, plus credentials in the URL, and
  look-alikes that pass; skipped domains with subdomains, trailing dots and IDN; skipped folders
  (whole word, blanks ignored); allow-list parsing and per-port matching; the User-Agent shape and
  `Accept-Language`; `safeFetch` with injected resolvers: policy skips before any lookup, a
  public name resolving to `127.0.0.1`, one private answer among public ones, the https upgrade
  checked too, a lookup failure. `test/fetch-wrapper.test.js` (unit against local `node:http`
  and `node:https` servers on `127.0.0.1`, allowed through `MNEMOS_FETCH_ALLOW_HOSTS`; TLS from
  `test/fixtures/tls/`, a self-signed certificate valid until 2126): https first, http fallback
  from a plain port, an untrusted certificate, a handshake that hangs past the 5 s upgrade limit and

- **Untested**: Brotli and deflate bodies; IPv6 connections (the servers listen on IPv4 only).
- **Tickets**: mnemos-tc4.8
