# Features and their tests

mnemos is a read-only MCP server (TypeScript, Node >=22.13, npm) that reads Chrome's `Bookmarks`
JSON file and answers five MCP tools over stdio. `src/lib.ts` holds all the logic,
`src/index.ts` is the MCP wiring, `src/icon.ts` is generated by `scripts/build-icons.mjs` from
`assets/`. Tests use Node's built-in runner (`node:test`) against the compiled `dist/` and the
synthetic fixture `test/fixtures/bookmarks.json`, injected through `CHROME_BOOKMARKS_PATH`.

## Suites

| Suite | Runner | Command | What it runs |
|-------|--------|---------|--------------|
| dependencies | `scripts/check-fast.sh` | `npm ci --ignore-scripts` | only when `node_modules` is missing or older than `package-lock.json` |
| build | `scripts/check-fast.sh` | `npm run build` | `tsc`, type-checks `src/` |
| unit tests | `scripts/check-fast.sh` | `npm test` | builds, then `node --test`, which finds `test/*.test.js` itself (118 tests, ~1s) |
| published package (e2e) | `scripts/check-full.sh` | `node --test e2e/package.e2e.js` | `npm pack --json` into a scratch directory (runs `prepare`, so builds again), unpacks the tarball with `tar`, checks its files and bin, starts the server through the bin (4 tests, ~2s) |
| embedding model (e2e, opt-in) | `scripts/check-full.sh` | `node --test e2e/model.e2e.js` | skipped unless `MNEMOS_E2E_MODEL=1`; then downloads the real model (about 135 MB) into a temporary cache directory and ranks an English query against Greek passages (2 tests, ~30s with the download) |
| semantic search acceptance (e2e) | `scripts/check-full.sh` (only with `MNEMOS_E2E_MODEL=1`), `.github/workflows/semantic.yml` | `node --test e2e/semantic.e2e.js` | packs the tarball, `npm install`s it into a clean directory from the registry, starts the installed bin on `e2e/fixtures/semantic/Bookmarks` (31 bookmarks pointing at a local fixture site) with the real model, waits for the titles, scores the golden queries of `queries.json` (every `must` query in the top 3, MRR ≥ 0.8), restarts on the same cache; prints a report and appends it to `$GITHUB_STEP_SUMMARY` (5 tests, ~15s with the model in `MNEMOS_E2E_MODEL_CACHE`, ~2 min with the download) |

`npm test` runs `node --test` with no file arguments, so Node's runner discovers the test
files: a new file named `test/<feature>.test.js` runs with no edit to `package.json`. On every
supported Node (checked on 22 and 24, which match glob patterns) the runner skips `node_modules/` and runs every `.js` file under `test/` and
every `*.test.js`, `*-test.js`, `*_test.js`, `test-*.js` or `test.js` elsewhere, `dist/`
included. So keep helper modules out of `test/` or give them no top-level side effects, and
keep test files out of `src/` (tsc would copy them into `dist/`, where they would run too).
Suites too slow for `npm test` live in `e2e/` with names none of those patterns match
(`<feature>.e2e.js`), and `scripts/check-full.sh` runs each by path.

Runner times on macOS, Node 24, three runs each with `node_modules` installed:

- `scripts/check-fast.sh`: about 2.3s warm (the first run after a build cache miss is slowest)
- `scripts/check-full.sh`: about 3.8s warm (check-fast, then packs, unpacks and starts the package)

CI (`.github/workflows/ci.yml`) runs `npm ci`, `npm test` and `node --test e2e/package.e2e.js`
on ubuntu, macOS and Windows with Node 22 and 24.
`.github/workflows/semantic.yml` runs `node --test e2e/semantic.e2e.js` on ubuntu with Node 22
for every push to main and pull request, and on ubuntu, macOS and Windows with Node 22 and 24
weekly and by hand; it caches the model, keyed on its pinned revision.
`test/node-floor.test.js` keeps `engines.node` (`>=22.13`, for `node:sqlite`), the lockfile's
root entry and that matrix in step.

## PDF bookmarks

- **Reached by**: the background page fetcher (`src/fetcher.ts`: `pdfExtraction`; see Background

  `application/x-pdf`, or a generic download type at a `.pdf` path, when the body starts with
  `%PDF-` (up to the 5 MB cap; `acceptPdf: false` skips PDFs); `src/pdf.ts`: `extractPdfText`,

  caps; encrypted, non-PDF and broken-xref files; an abort before and during extraction; a parser

## Background title indexing

- **Reached by**: every server start: `src/index.ts` calls `Indexer.start()` once
  `server.connect()` returns; `src/indexer.ts` (`Indexer`, `urlWords`, `embeddingText`,
  `bookmarkRows`, `clipDescription`). Each bookmark's text (title, description from `lib.describe`
  clipped to 300 characters, folder path, URL words) is hashed and its description kept in the store's `description` column; rows are
  synced into the index store, and only those without a vector (new, changed text, or a new
  model) are embedded, as `passage`, in batches of 32. `checkForChanges()` (for
  `semantic_search`) re-indexes, debounced, when the file's mtime or size changed or the last
  run failed. Errors go to `status()` and stderr, never into a tool. The server-spawning tests
  set `MNEMOS_CACHE_DIR` to a temporary directory and `MNEMOS_EMBEDDER=fake`, so they never
  touch the user's cache or the real model.
- **Tests**: `test/title-index.test.js`: e2e (SDK client over stdio, fake embedder, temporary
  cache, a copy of the fixture): `initialize` and a tool call return while the fake's gate
  holds embedding back, then every fixture bookmark gets a 384-dim vector and its text is
  embedded once; a second start embeds nothing; an added, a renamed and a deleted bookmark
  re-embed exactly the two changed texts. In process: `start()` reads nothing on the caller's
  turn, progress counts titles; three `checkForChanges()` calls on a changed file run one
  re-index after the debounce and none on an unchanged one; a failing embedder, a missing
  Bookmarks file and an unusable cache directory end in a `failed` status (logged once) and
  are retried by the next check; a new model revision re-embeds every title; row keys

  `urlWords` (no www or TLD, country second-level domains, path split on `/ - _ .` and

## semantic_search: cutoff by library size, model start

- **Reached by**: `semantic_search` (`src/semantic.ts`). The margin over the median title
  (`relevanceMargin`) is the embedder's `margin` scaled by √(ln N / ln `marginTitles`) for N
  embedded titles (the real model's: 0.065 at 2,300 titles, about 0.043 at 31); the fake has no
  `marginTitles`, so its margin is used as it is. A model that has not started (after a restart
  no title needs embedding, so nothing else loads it) is started by the query, which waits for
  it as for any query vector.
- **Tests**: `test/semantic-margin-size.test.js`: `relevanceMargin` unscaled without
  `marginTitles`, exact at it, √(ln N / ln `marginTitles`) of it elsewhere, 0 for one title,
  growing with N; `MODEL_RELEVANCE`'s values; in process, a margin calibrated on a larger
  library keeps a hit the unscaled one cuts. `test/semantic-model-start.test.js` (in process,
  a stand-in model `not_started` until its first `embed()`): the query starts it and is
  answered semantically; a model that cannot load gives keyword results with the reason; one
  still loading when the query gives up keeps loading and answers the next query.
  `e2e/semantic.e2e.js` (see Suites): the real model, golden queries and a restart.

## Index freshness

- **Reached by**: the background fetcher's refill (`src/fetcher.ts`: `pageResult`, `backoffMs`,
  `Fetcher`'s `applyPolicy`) and the indexer's sync (`IndexStore.syncBookmarks`). Every stored
  outcome sets `pages.next_attempt_at`: an `ok`, `needs_login` or fetch-skipped page is due
  `REFRESH_MS` (30 days) after its fetch, a `failed` one after `BACKOFF_STEPS_MS` (1 h, 6 h,
  1 d, 7 d, then 30 d) by its `fail_count`, which carries over until a fetch succeeds; a
  `no_content` page (no text even in the browser) has none and is final. A re-fetched page whose `content_hash` is unchanged is not cut or embedded again.
  The fetch policy (`fetchConfig`, as JSON in the `fetch_policy` meta key) is compared at each
  refill; when it changed, `needs_login` pages and pages the fetch itself skipped (a redirect
  to a skipped domain, a private address) are due at once. Pages a skip list covers are
  `skipped` with no next attempt and their chunks dropped, and go back to `pending` once no
  skip list covers them (the list edited, or the bookmark moved out of a skipped folder). A
  deleted bookmark's row goes at the indexer's next run, with its page and chunks unless
  another bookmark has the URL. The fetcher, indexer and store take a `now` clock.
- **Tests**: `test/index-freshness.test.js` (in process, an injected clock, a fake fetch and a
  counting fake embedder on one index): an ok page not fetched at 29 days and fetched at 31,
  its unchanged text not embedded again and a changed one embedded; a failing page retried
  exactly at 1 h, 6 h, 1 d, 7 d, 30 d and 30 d and not a minute before, then recovering with
  its count reset; `needs_login` and a redirect's skip not fetched again at 29 days, fetched
  once on a policy change and once 30 days later; a deleted bookmark's page and chunks gone,
  a URL still bookmarked in another folder kept and never the deleted one fetched; skip-list
  edits skipping pages (chunks dropped, not fetched 31 days on) and un-skipping them.
- **Untested**: two processes with different skip lists taking the lease in turn (each change
  of holder retries the `needs_login` and skipped pages once).
- **Tickets**: mnemos-tc4.4; mnemos-tc4.13 (acceptance on GitHub)

## Page chunks

- **Reached by**: the indexer (`src/indexer.ts`), after each title pass and, debounced, after the
  fetcher stores a page (`Fetcher`'s `onPage` calls `Indexer.pagesChanged()`, a run of the page
  pass alone); `src/chunk.ts` (`chunkText`, `estimateTokens`, `chunkEmbeddingText`). An `ok`
  page whose `content_hash` is not the `pages.chunked_hash` its chunks came from (schema version
  3) is cut into chunks of about 350 tokens (estimated from characters by script: ¼ token per
  ASCII character, 1 per Chinese/Japanese/Korean one, 0.4 otherwise) on paragraph and sentence
  boundaries (`Intl.Segmenter`), a longer sentence at a space or a character, each chunk starting
  with about 15% of the one before, at most 40 per page; a page that lost its text (no longer
  `ok`, and not just `failed`) loses its chunks. Chunks without a vector are embedded as
  `passage`, the bookmark's title (150 characters at most) on the line before, 8 at a time with
  a yield between. `semantic_search` ranks a bookmark by the better of its title and its page's
  best chunk (`matched_on: "page"` with a snippet that starts near the first query word); the
  progress line's `pages y/N` counts pages whose chunks are all embedded.
- **Tests**: `test/page-chunks.test.js`: unit: `estimateTokens`; `chunkText` on empty and short
  text, sentence boundaries with 15% overlap and nothing lost, paragraphs, a sentence longer than
  a chunk, Chinese and Greek without spaces, the 40-chunk cap; `chunkEmbeddingText`; `snippet`
  near the query words. Store: `pagesToChunk`, `embeddedPageCount`, the version 2 to 3
  migration. In process (`Indexer` with a counting fake embedder): chunks embedded after the
  title, the same text fetched again embeds nothing, new text is cut again, a login wall drops
  the chunks, leftover chunks are embedded at the next start. e2e (SDK client over stdio, fake
  embedder with `MNEMOS_FAKE_EMBED_LOG`, a `node:http` fixture site): words only in a page's
  body find it with `matched_on: "page"` and a snippet holding them; after a restart that
  re-fetches both pages, the unchanged one is not embedded again and the changed one is.
- **Untested**: the real model on page chunks (`e2e/semantic.e2e.js` scores titles only); two
  processes embedding the same chunks at once (harmless: the same vectors are written twice).
- **Tickets**: mnemos-tc4.10; mnemos-tc4.4 (re-fetching after 30 days); mnemos-tc4.13

## Headless browser rendering

- **Reached by**: the background fetcher, for a page whose plain fetch has under 200 characters
  of readable text: it is stored `needs_browser` (its fail count kept) and queued for the
  browser; `src/headless.ts` (`resolveBrowser`, `HeadlessBrowser`) and `src/policy-proxy.ts`
  (`PolicyProxy`). The browser is `MNEMOS_BROWSER` (a path; `0` turns rendering off), else
  Playwright's channels chrome, chrome-beta, chrome-dev, chrome-canary and msedge, else Chromium
  and Brave where they install; driven by playwright-core, an optionalDependency loaded with
  `import()`. Launched on the first such page, at most 2 pages at once under the fetcher's
  per-domain rules, closed once none is left and on stop; a fresh temporary profile, deleted on
  close; images, media and fonts dropped; route interception applies `checkUrl` (all of it to
  the page, the host rules to what it loads), and every connection, redirect hops included, goes
  through a local proxy that checks the host and its DNS answers. 20 s per page, then the
  network idle or 3 s; Readability on `page.content()`. The result is stored as a plain fetch's
  would be, except that no text is `no_content` for good. With no browser, no playwright-core or
  rendering off, pages stay `needs_browser` and `semantic_search`'s `status.browser` says
  "N pages need a browser; set MNEMOS_BROWSER" (or what is missing).
- **Tests**: `test/headless-resolve.test.js` (unit, injected file system and environment): each
  step of the order wins over the later ones, the order itself, nothing found, `0`, a path that
  is not there, macOS home Applications, Linux and Windows paths and prefixes.
  `test/headless-fetcher.test.js` (in process, a fake renderer): JS shells rendered from their
  final URL and stored `ok` with the rendered text, at most 2 in the browser, one launch and one
  close; no launch without such pages; a failing render backs off, an empty one is
  `no_content`; playwright-core absent (a `HeadlessBrowser` whose import rejects) and no browser
  found leave pages `needs_browser` with the note, crash nothing, and a later run with a
  browser renders them without fetching them again. `test/policy-proxy.test.js`: plain requests
  and CONNECT tunnels reach an allowed host; local names, private literals, names resolving to
  a private address and DNS failures are refused before connecting.
  `test/headless-render.test.js` (e2e, a real installed browser; skipped with the reason when
  none is found): a page that builds its text with JavaScript ends `ok` with it; its requests
  to a blocked host, direct and through a redirect, never arrive; images are not loaded; the
  temporary profile is gone after close.
- **Untested**: Windows and Linux browsers for real (CI's runners may have none); a browser that
  crashes mid-page; the 20 s limit with a real slow page.
- **Tickets**: mnemos-tc4.5
